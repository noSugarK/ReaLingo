# Tauri 2 + Rust + Vue 应用开发

完成用户指定的功能，并用目标平台上的行为和成品证明它工作。共享业务逻辑、平台原生能力和界面布局分别决策；浏览器预览、主机测试、目标编译和设备运行是不同证据。

## 开始实现前

检查现有 `package.json`、Cargo manifest/lockfile、Tauri 配置、capabilities、原生覆盖文件和 CI，确认目标系统、最低版本、架构与实际依赖版本。优先沿用现有入口、插件和构建脚本。新项目使用当前 Tauri CLI 支持的 Vue + TypeScript 模板；先跑通最小窗口和一个真实 command，再引入平台功能。

先确定本次改动落在哪一层，再按需读取：

| 本次工作 | 读取材料 |
| --- | --- |
| Vue/Rust 边界、状态同步、配置持久化、双端界面 | [共享实现](references/implementation.md) |
| Windows/macOS/Linux 窗口、托盘、音频、权限或安装 | [桌面集成](references/desktop.md) |
| Android 原生桥、权限、文件、后台任务、悬浮窗；或评估 iOS | [移动集成](references/mobile.md) |
| 目标编译、测试、签名、版本升级、发布和下载页 | [验证与发布](references/verification-release.md) |
| 对照 ReaLingo 中已发生的故障、修复和证据 | [案例索引](references/realingo-cases.md) |

材料中的目录形状是可选实现示例；平台最低版本和依赖版本是案例条件，不是所有项目的固定要求。

## 实现顺序

1. **界定可观察结果。** 指出用户要改的控件、行为、目标平台和验证入口。局部图标修改保留原介绍和布局；“移动端支持”需要原生功能证据，不能只缩窄桌面窗口。
2. **贯通一条路径。** Vue 输入 → 类型明确的 IPC → Rust 业务/平台实现 → 可查询的结果/错误 → Vue 展示。需要权限或选择器时把取消、拒绝、失败作为正常结果设计。
3. **补齐生命周期。** 对长任务确定开始、就绪、停止、结束的所有者；旧任务不能覆盖新任务。后台资源由能在后台运行的原生层持有，前端恢复后查询状态。
4. **按变更选证据。** UI 查窄屏、长内容、主题和无障碍名称；共享逻辑跑对应检查；原生改动编译目标并运行关键路径；发布改动核对最终安装包。小改动复用已有验证，不机械跑无关平台。

完成时说明实际改了什么、在哪些系统/架构验证、哪些设备路径尚未覆盖。编译通过只报告为编译通过；设备权限、音频帧、网络上传和服务端响应分别报告。

## 贯穿各层的约束

- Rust 持有跨界面的业务状态和资源生命周期；Vue composable/纯函数共享客户端规则；Kotlin/Swift 或已有插件处理系统权限、Activity/原生 UI 和系统文件接口。小项目按需拆分，不为了跨平台预建一套未使用的抽象。
- Rust 用目标 `cfg` 和目标依赖隔离不可用 API；前端用后端能力报告决定操作是否可用。UA 仅可作首屏提示，窗口宽度不代表系统能力。
- 插件必须同时具备后端注册、前端匹配 API 和适用窗口的权限/作用域。自定义 Rust commands 还要在自身边界验证参数；capabilities 不能替代业务输入校验。
- 有副作用的桥接只暴露给可信应用页面；外部链接用 opener 交给系统。以真实的密钥存储、签名和数据流填写产品文案，不把应用私有目录里的明文配置称为系统密钥库。
- 发布、推送、发信等外部动作遵循本次用户的授权范围。技能本身不授权发布；已有明确授权时继续执行，不重复增加确认步骤。
